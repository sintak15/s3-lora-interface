# Build and verification

`config/build-dependencies.json` records the exact toolchain and library versions
used to verify this firmware. `tools/check_build_environment.ps1` checks them
before the OTA build script changes the version or creates a binary.

| Dependency | Pinned version |
| --- | --- |
| Espressif Arduino ESP32 core | 3.3.7 |
| LVGL | 8.3.11 |
| TFT_eSPI | 2.5.43 |
| TinyGPSPlus | 1.0.3 |
| Nanopb runtime | `nanopb-1.0.0-dev`, exact source hashes in the lock file |

Install the released dependencies with Arduino CLI:

```powershell
arduino-cli core install esp32:esp32@3.3.7
arduino-cli lib install "lvgl@8.3.11" "TFT_eSPI@2.5.43" "TinyGPSPlus@1.0.3"
```

The Espressif package index must already be configured in Arduino CLI/IDE.
The checked-in Meshtastic protobuf files were generated by nanopb 0.4.9.1.
The runtime is the verified development snapshot vendored, without source
changes, in `src/nanopb/`. No separate nanopb installation is required. Its version
string alone does not identify the source, so the preflight checks all seven
runtime source/header hashes against the lock file. The original copyright and
license are preserved in `src/nanopb/LICENSE.txt`. Updating the runtime requires
updating those hashes and rerunning verification.

The LVGL configuration is now checked in as `config/lv_conf.h` and selected
through `LV_CONF_PATH` in `build_opt.h`. It enables RGB565, PSRAM allocation,
and the fonts used by the UI. There is no need to edit a shared Arduino library
configuration. TFT_eSPI uses the checked-in `tft_setup.h`.

Notification audio uses GPIO8 to feed the ES8311 DAC, unity codec gain and a
dedicated PCM task. Short boops and bubble pops have separate message/direct
selections. The Sound page and browser preview respect saved selections and volume.
USB `audio` reads playback/codec status; `audio-recover` requests a bounded
reinitialization without playing a sound. See [notification audio](AUDIO.md).

The board configuration is:

```text
esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi,CDCOnBoot=cdc,DebugLevel=info
```

Run repository checks, browser tests and firmware compilation together:

```powershell
.\tools\verify_firmware.ps1
```

Python 3.10 or later runs `tools/check_repo.py`; Node.js 18 or later runs the
browser tests. Pass `-Python`, `-Node` or `-ArduinoCli` to provide explicit
executable paths. Repository checks validate local documentation links, OpenSCAD
dependencies, JSON/Python syntax, generated-file placement and the README version.
The verifier builds under `build/verify` without incrementing the firmware version. Its
`FIRMWARE_RUN_TESTS` flag enables compile-time C++ checks for decimal overflow,
malformed settings, serial framing, truncated frames, repeated header bytes,
and timer wraparound. The JavaScript checks cover injected names, overlapping
refreshes, HTTP/network failures, backoff, recovery, request timeouts and saved
sound-selection previews. Sound checks preserve numeric preference IDs and
verify bounded pitches, duration and envelopes.
GPS checks cover UBX framing, read/ACK/readback sequences, partial reads, rejected
or mismatched settings, command timeouts, save masks and rate/output/power ordering.
GPS sharing checks cover stale/invalid fixes, local-only packet destinations,
queue-result matching, retry cadence, timer wrap, UTC timestamps, units and
preservation of unrelated Heltec position settings.
Display formatting checks cover separate label/value colors, multiple readings
on a line, MAC/time colons, literal hash characters and bounded output.
MAX17048 checks cover register units, signed CRATE, fractional/zero SOC and
failed rate reads. Voltage-variation checks cover known sample statistics,
window resets and steps across record boundaries. Web checks cover single
logging requests, explicit SD failures and uncertain connection-loss outcomes.

Host-side USB protocol tests run without connecting to a device:

```powershell
python -m pip install pyserial Pillow pyshp
python -m unittest discover -s tests -p "test_*.py"
```

The optional browser checks for settings/navigation and offline maps additionally
require Playwright and its Chromium runtime:

```powershell
python -m pip install playwright
python -m playwright install chromium
python tests/test_web_navigation.py
python tests/test_web_offline_map.py
```

Both build scripts generate the ignored `config/build_identity.generated.h`
with the full Git commit and a flag for modified or untracked source. Firmware
built directly in Arduino IDE without that header reports `unknown` source.
Use the scripts to refresh this identity before building after source changes.

## Field tools

- Chat's **Message Delivery** table shows the latest ten attempts and offers
  per-message retry. The touchscreen **TX Log** shows the same states and has
  **Retry Last**. History is held in RAM and clears on reboot.
- **Queued** means written to the UART; **sent to radio** means the Heltec
  accepted the packet into its queue. A local echo is labeled separately.
  **Acknowledged** on a direct message means its destination returned a routing
  ACK. **Mesh acknowledged** on a broadcast means the Heltec reported an implicit
  ACK after hearing a relay; it does not confirm every recipient or that anyone
  read the message. See the [Meshtastic mesh algorithm](https://meshtastic.org/docs/overview/mesh-algo/).
- Explicit queue/routing errors show **failed**. After two minutes without a
  result, an attempt becomes **unconfirmed**, since it might have arrived.
  Only failed/unconfirmed attempts can be retried. A retry keeps the full
  original text (up to 233 UTF-8 bytes), destination and channel, creates a new
  packet ID, and may create a duplicate at the recipient. Each original attempt
  can be retried once; the resulting attempt can itself be retried after failure.
- The Heltec health banner and screen indicator use the last valid decoded
  response: **responsive** under 45 seconds, **quiet** from 45 to 89 seconds,
  **stale** at 90 seconds. Heartbeats run every 30 seconds. This measures the local
  serial connection, independently of how busy the LoRa mesh is; quiet/stale
  does not prove a wiring failure.
- Battery percentage comes from MAX17048 SOC without a voltage-derived trim.
  Runtime uses a persisted discharge rate with fresh SOC at startup, then blends
  consistent gauge-rate readings and measured SOC decline as evidence arrives.
  Charging and unreliable readings pause estimation without erasing the learned
  rate. The UI identifies previous use, gauge trend and current use, with time
  rounded to five minutes. See [battery statistics](BATTERY_STATS.md) for learning,
  persistence, gauge trend, SD power logging and measurement limitations.
- At USB **115200 baud**, send `version` followed by a newline for firmware,
  full source commit, modified-source flag, build date/time and active partition.
  Send `diagnostics` for a single-line JSON health report among the usual logs.
- In web Diagnostics or SD Storage, **Download Field Report** downloads the same
  authenticated `/diagnostics/report` JSON directly, without requiring an SD
  card. It includes firmware identity, uptime/reset reason, radio counters,
  battery, memory, SD health and aggregate delivery states. It omits passwords,
  channel keys, message contents and coordinates. The existing full status
  snapshot remains available separately.

The verifier also checks delivery timeout/queue transitions, ACK source matching,
timer wraparound, runtime estimation/reset rules, escaped delivery rendering,
and retry request handling. Hardware acceptance should cover a successful direct
ACK, an unreachable target/NAK, broadcast implicit ACK, a disconnected Heltec,
a ten-minute battery discharge, and a downloaded report.

Create an OTA binary using the existing script:

```powershell
.\tools\build_ota_bin.ps1 -NoVersionBump
```

Device configuration still comes from the ignored
`config/device_config.local.h`, falling back to
`config/device_config.example.h`. Never commit device passwords or tokens.

## Hardware checks

Compilation and fake-browser tests cannot verify UART wiring, SD latency, or
actual radio delivery. Before flashing devices used in the field:

1. Confirm configured channels load, then send on each enabled channel.
2. Submit malformed settings and `channel=ch:abc`; verify HTTP 400 and no radio
   transmission or configuration change.
3. Download a large SD log with a slow client while receiving radio traffic;
   check that the screen stays responsive and radio counters continue.
4. Disconnect/reconnect the download client and confirm another download works.
5. Interrupt a serial frame, pause at least 250 ms, then send a valid frame;
   check the frame timeout counter and decoding recovery.

Only one SD download runs at a time. It sends at most one 1 KiB chunk per loop,
holds the SD mutex only during file operations, and abandons clients that make
no progress for ten seconds. SD remount requests return HTTP 409 while a
download is active. Chat sends require a loaded, enabled channel; request radio
configuration first if the device has just booted.
Saving a status snapshot returns HTTP 409 while that snapshot is being
downloaded, and map-cache writes are skipped during a map-cache download so
those files cannot be truncated partway through the transfer.

## Source layout

`s3-lora-interface.ino` contains hardware initialization and the main loop.
Implementation lives in `src/firmware/`:

| File | Responsibility |
| --- | --- |
| `State.h`, `Declarations.h` | Shared types/state and internal function interfaces |
| `Runtime.inc` | Runtime buffer allocation |
| `Storage.inc` | SD storage, logging, and append worker |
| `Gps.inc`, `Battery.inc` | Local GPS, fuel gauge, and diagnostics |
| `BatteryCycle.inc` | Battery/power health recorder and SD cycle controls |
| `GpsRelay.inc` | GPS sharing over Protobuf UART and verified Heltec setup |
| `GpsUi.inc` | GPS Config and Adv pages, shared draft and confirmed-setting display |
| `Network.inc` | Event logs, preferences, WiFi, and scanning |
| `DisplaySettings.inc`, `Audio.inc` | Display settings and notification audio |
| `Ui.inc`, `UiRefresh.inc` | Touch UI construction and updates |
| `Map.inc` | Offline map cache and render worker |
| `TileCache.inc`, `MapBenchmark.inc` | Tile LRU cache and read-only profiling |
| `MapUi.inc`, `MapCoverage.inc`, `MapCoverageUi.inc` | Navigation, coverage and map UI |
| `WebMap.inc` | Offline browser tile serving and storage-generation handling |
| `UsbTiles.inc`, `UsbSdExport.inc` | USB tile upload and read-only file export |
| `HomeUi.inc`, `*Tests.inc` | Home dashboard and verification-only device checks |
| `Radio.inc` | Meshtastic packets, configuration, chat, and serial parser |
| `Http.inc` | Status JSON, HTTP handlers, downloads, OTA, and route registration |

These `.inc` files are included once in the main sketch, preserving one
translation unit and existing ownership of shared state. Internal interfaces
are explicit, rather than depending on Arduino-generated prototypes.
`src/Reliability.h` contains the platform-independent framing and integer parser;
`src/WebValidation.inc` defines route-specific numeric limits.
`src/NotificationSound.h` owns sound IDs, labels, patterns and rounded envelopes.
`src/GpsConfig.h` owns the portable GPS command state machine and validation;
`src/GpsUbx.h` builds and decodes bounded UBX packets.
`src/GpsRelay.h` owns GPS sharing freshness/cadence, local packet construction,
position conversion and bounded setup timing.
The sketch-level `pb*.h` forwarding headers select the vendored nanopb runtime
for both application code and generated Meshtastic headers.
