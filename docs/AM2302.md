# Outside-case AM2302 / DHT22

The existing AM2302 measures outside temperature and relative humidity. It uses
one DIGITAL GPIO, not I2C and not ADS1115. No BME280 is required.

## Connections (all power removed while wiring)

| AM2302 terminal | Connection |
| --- | --- |
| VCC / supply | CYD 3V3 |
| GND | Common system GND |
| DATA | CYD expansion GPIO2 |

Use a 4.7-10 kohm pullup from DATA to 3V3 if the sensor assembly does not already
contain an equivalent pullup. Add 100 nF between VCC and GND near the sensor.
Identify actual terminals/wires from the sensor labeling, not assumed colors.
Keep wires short, initially about 20-30 cm, and verify operation before extending.
Use 3.3 V for BOTH supply and data pullup; do not pull data to 5 V.

GPIO2 was previously GPS TX. Disconnect any GPS RX wire from GPIO2. ATGM336H
TX still connects to GPIO3; its RX remains disconnected. Firmware initializes
GPS UART1 with explicit RX=3 and TX=-1, so it does not drive GPIO2. This behavior
was checked in the pinned Arduino-ESP32 3.3.7 core. Reverting to a u-blox receiver
with TX=2 automatically disables the default AM2302 pin; compile-time checks
reject explicitly configured GPS/sensor pin collisions.

Do NOT use the UART0 GPIO43/44 header or native USB GPIO19/20 for this sensor.
The USB port, Serial USB diagnostics and Heltec UART wiring are unchanged.

## Connection budget

| Function | CYD GPIOs |
| --- | --- |
| Heltec UART2 | RX14 / TX21 |
| ATGM336H UART1, receive only | RX3; no TX pin |
| AM2302 digital data | 2 |
| Shared I2C: touch, codec, ADS1115 | SDA16 / SCL15 |
| Native USB | 19 / 20, untouched |
| UART0 header | 43 / 44, untouched |

There is no extra CYD analog pin requirement. ADS1115 A0 is cell voltage,
A1 is boosted 5V via its divider, A2 is TEMT6000, and A3 stays free. Supply and
GND must fan out to multiple modules using a splitter/distribution connection.

## Firmware behavior and checks

Default AM2302_DATA_PIN=2. Set it to -1 in device_config.local.h to disable.
After startup the first attempt waits 5 seconds; subsequent requests are 5
seconds apart, respecting the sensor's minimum interval above 2 seconds.
The host start pulse blocks for 1.2 ms; CHANGE interrupts capture the reply,
without masking interrupts for the entire frame. Handshake, pulse widths,
40-bit length, checksum and -40..80 C / 0..100% RH ranges are checked. A missing
or malformed response times out; failed data is unavailable, not zero.
A reading older than 15 seconds is also unavailable. Errors retry automatically.
This capture implementation still needs bench testing with the actual sensor.

Outside temperature/humidity appear on System > Battery beside the analog
sensors, web Health, diagnostic JSON and readable SD power-health logs. API keys
are environmentAvailable, ambientTemperatureC, ambientHumidityPercent,
environmentAttempts and environmentErrors. Unavailable measurements are null;
values are Celsius and % RH. Legacy CSV structure stays unchanged.

On first use, confirm a plausible room reading, then gently warm the sensor
with a hand and check temperature responds. Do not breathe moisture directly
into its vents or immerse it. To test unplugged behavior, power down, unplug the
sensor, and power up; readings must become unavailable and errors increase.
Confirm USB diagnostics, GPS, radio, touch and audio remain responsive.

## Future enclosure mounting

Expose the vented sensing body on the selected side, with electronics/wiring
inside. Reserve space for a removable clip and cable strain relief; measure the
actual sensor before designing that opening. Leave vents open and separate the
body from screen, charger, boost and warm internal airflow. Shield from direct
sun, rain, splashes and condensation; the exposed sensor is not waterproof.
Do not put sealant, glue or coating on the sensing vents. A sheltered vented hood
can protect against splashes while allowing ambient airflow. Enclosure CAD has
not been changed yet.
